# 梅花易数人工解卦协议 v1

## 结论

人工解卦必须先判断“方向”，再判断“应期”；先确定事件自然尺度，再使用卦数、动爻或卦气收窄时间。任何单一卦名、单一动爻数字或单一五行关系都不能独立推出具体结果。

固定状态：

```text
interpretation_status=review_only
production_allowed=false
prediction_validity=not_evaluated
maximum_outcome_confidence=medium
```

确定性排卦事实可以标为高置信；现实事件的方向和应期在完成前瞻验证前最高只能标为中置信。

## 一、固定研判顺序

### 1. 复述并确认事件合同

只确认：事件类别、目标事件、成功标准、截止日、当前阶段和现实硬条件。不得在这一阶段自行猜测隐私内容。

### 2. 复核结构

确认：

- `profile_id`；
- 原始数字与顺序；
- 本卦、互卦、变卦；
- 动爻；
- 体卦与用卦；
- 是否存在排卦冲突。

结构未通过不得进入解释。

### 3. 判断基础动力

体用关系只说明主体与外部条件之间的结构倾向：

```text
用生体
体用比和
体克用
体生用
用克体
```

必须结合事件主题、时令和现实阶段。不得把“用生体”直接写成高概率成功，也不得把“用克体”直接写成必败。

### 4. 看主、互、变的连续过程

- 本卦：起点和当前状态；
- 互卦：中间机制、隐藏环节或过渡阶段；
- 变卦：动爻发生后进入的后续状态。

三者必须组成一条可验证的过程链，不能分别讲三套互不约束的故事。

### 5. 看动爻位置

动爻用于判断变化发生在内外、早中晚和哪一半结构中。动爻数字可以参与应期，但不能单独决定应期单位。

### 6. 加入已确认的时令

只有在月令、季节或历法上下文已经由可靠来源确认时才使用。未经确认的日柱、节气、农历月份不得由解释者临时猜测。

### 7. 主题映射

只取与目标事件直接相关的象，不罗列所有万物类象。不得根据客户后续透露的事实反向挑选最像的象。

### 8. 现实校正

资格、官方审批、法律限制、健康状况、资金、距离、对方明确态度等现实证据优先。卦象不能覆盖已经确认的硬阻断。

### 9. 形成方向判断

方向只允许：

```text
leans_toward_success
leans_toward_failure
mixed_or_conditional
unresolved
```

必须同时写成立条件和反证条件。

### 10. 再做应期判断

先从事件合同读取自然时间单位，再用至少两类相互独立的时序证据收窄窗口。

## 二、应期尺度

| 事件 | 优先自然单位 |
|---|---|
| 即时消息、临时见面 | 小时、日 |
| 短期物流、一次面试结果 | 日、周 |
| 考试、求职、普通搬迁 | 周、月 |
| 长期迁居、身份审批 | 月、季度 |
| 婚姻、长期事业转型 | 月、年 |

同样是二爻动：

- 日级事件可以参考 2 日；
- 周级事件可以参考 2 周；
- 身份迁移可以参考第 2 个月或第二阶段；
- 不能不看事件尺度统一解释成“两天”。

## 三、压缩到具体日期的门禁

只有同时满足以下条件，才允许低置信给出具体日期观察点：

1. 事件天然属于日级或小时级；
2. 成功标准只有一个瞬时节点；
3. 至少两类时序证据指向同一窄窗口；
4. 现实流程允许在该日期完成；
5. 已明确主窗口和后备窗口；
6. 输出清楚标注“观察点”，不得写成保证日期。

长期迁移、身份、婚姻和长期事业默认不得直接报某一天。

## 四、迁移类专用拆分

`migration_identity` 必须分别考虑：

1. 资格或身份获批；
2. 出发日期确定；
3. 实际离开；
4. 到达目标地；
5. 身份或登记生效；
6. 稳定居住。

一次预测只选择其中一个目标节点。若客户问“彻底迁移何时完成”，成功标准必须同时包含身份生效和实际稳定居住；前面的通知、批复或出发只能记录为过程事件，不能提前算命中。

## 五、问题漂移处理

如果初始问题是“某件事哪天成”，之后才补充为“身份、长期居住地和生活轨迹完全改变的远距离迁移”，必须：

- 标记原判断为 `QUESTION_DRIFT`；
- 原来的日级应期停止使用；
- 重新确认 `migration_identity` 的成功标准和截止日；
- 新判断作为新版本发布；
- 原判断不计入命中率。

这不是“同一卦越断越细”，而是事件合同已经改变。

## 六、证据与置信度

### 高置信

只用于可复算的结构事实，例如本卦、互卦、变卦、动爻和体用。

### 中置信

可用于现实结果倾向，但至少需要：

- 输入合同完整；
- 排卦结构唯一；
- 两条以上相互独立的支持链；
- 无已知现实硬阻断；
- 有明确反证条件。

### 低置信

出现以下任一情况：

- 客户隐藏了事件类别或成功标准；
- 没有截止日；
- 只靠一个卦名、一个动爻数字或一句爻辞；
- 时令未确认；
- 现实阶段未知；
- 存在问题漂移或重复起卦。

## 七、输出合同

### 评论区版

```text
【结论｜中/低置信】一句话说明偏成、偏不成或条件性。
依据：最多 2—3 个直接相关结构，不堆术语。
时间：先给主窗口，再给后备窗口；长期事项不硬报单日。
条件：说明最可能推动或拖延结果的现实因素。
反证：到何时出现什么情况，就必须降低或撤回判断。
仅供文化研究与娱乐参考。
```

### 付费版

必须增加：

- 资料和事件合同确认；
- 方向判断与应期判断分开；
- 主、互、变的连续过程；
- 现实条件和反证；
- 主窗口、后备窗口及各自对应的事件节点；
- 未验证假设和不确定性来源。

## 八、禁止事项

- 看到“解”就直接断解决；
- 看到“豫”就直接断吉或凶；
- 把互卦当成独立结果；
- 客户补充信息后不标记版本变化；
- 用模糊词同时覆盖批复、出发和落地；
- 主窗口没发生就无限向后顺延；
- 把“用生体”等结构关系写成具体概率；
- 用客户情绪或期待调整结论；
- 通过事后新增象意把失败解释成命中。
