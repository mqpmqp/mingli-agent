# 梅花易数人工研判治理 v1

## 结论

本阶段只建立四个必须先固定的合同：输入门禁、确定性排卦协议、人工解卦协议、前瞻结算协议。

固定状态：

```text
review_state=draft
runtime_enabled=false
production_allowed=false
prediction_validity=not_evaluated
commercial_accuracy_claim_allowed=false
```

本阶段可以直接用于人工咨询前的资料检查、排卦复核和案例封存，但不能据此宣称梅花易数的现实预测准确率已经得到验证。

## 为什么先做治理而不是继续堆象意

人工梅花最常见的失真不是“不会背卦”，而是：

- 起卦口径未声明，两数法、三数法或应用内部算法被混用；
- 问题最初过于模糊，客户补充信息后事件类别发生变化；
- “能成”没有唯一成功标准，批复、出发、到达、身份生效和稳定居住被混成一个节点；
- 动爻数字被直接机械换算成天数；
- 后续解释覆盖原预测，无法判断真实命中与否。

因此，任何正式判断都必须按以下顺序执行：

```text
输入门禁
  -> 选择并冻结排卦 profile
  -> 复算本卦/互卦/变卦/动爻/体用
  -> 冻结事件合同
  -> 人工研判并发布预测版本
  -> 结果出现后独立结算
```

## 文件索引

1. [输入门禁](INPUT_GATE_V1.md)：冻结事件类别、成功标准、截止日、现实阶段、隐私最小字段和问题漂移规则。
2. [确定性排卦协议](CASTING_PROTOCOL_V1.md)：冻结八卦数序、爻序、两数法与三数法 profile、互卦与变卦算法、体用划分。
3. [人工解卦协议](INTERPRETATION_PROTOCOL_V1.md)：固定研判顺序，分离方向判断与应期判断，规定迁移类多节点拆分和评论区输出合同。
4. [前瞻结算协议](SETTLEMENT_PROTOCOL_V1.md)：冻结预测版本、事件发生时间、取证时间、命中类别、问题漂移及不可计数规则。
5. [合成案例模板](templates/CASE_RECORD_V1.json)：只用于结构和流程验证，不计入真实预测样本。

## 强制门禁状态

| 状态 | 含义 | 是否允许继续断卦 |
|---|---|---|
| `READY` | 输入、profile、事件合同均唯一 | 是 |
| `NEEDS_CONFIRMATION` | 存在可由客户确认的缺项或歧义 | 否 |
| `INPUT_CONFLICT` | 原始数字、顺序、时间或排卦结果互相冲突 | 否 |
| `QUESTION_DRIFT` | 事件类别、目标事件或成功标准在预测后发生改变 | 原版本停止；创建新合同 |
| `REPEAT_CAST` | 同题短期重复起卦但未说明首卦 | 否 |
| `DATA_INSUFFICIENT` | 无法确定事件尺度、成功标准或现实阶段 | 只能低置信谈一般趋势，不得给精确应期 |

## 隐私边界

客户可以不披露具体人物、国家、机构、证件或敏感原因，但至少必须提供：

- 事件类别；
- 抽象但唯一的目标事件；
- 可核验的成功标准；
- 截止日期或可接受的最长时间；
- 当前流程阶段；
- 会直接阻断事件的现实条件。

例如“某件隐私事项什么时候成”不足以进入应期判断；“远距离迁移，目标是身份正式生效并已实际入住新居住地”可以在不披露敏感细节的情况下进入低至中置信研判。

## 当前能力边界

- 仅把人工起卦数据转换为唯一结构，不自动计算公历转农历、节气、月令或真太阳时。
- 不自动生成吉凶、概率、具体日期或自然语言预测。
- 不把体用生克当作现实概率。
- 不把卦名直接映射成“必成”“必败”。
- 不把回顾性案例、客户主观“觉得准”或问题补充后的改判计入准确率。
- 真实案例不得提交到仓库；只能保存去标识的结构摘要，且须有明确授权。

下一阶段只有在本协议稳定、合成结构检查通过并建立合格前瞻记录后，才考虑实现确定性排卦代码。任何解释规则仍保持 `draft`。
